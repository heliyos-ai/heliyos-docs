## List scouts

`heliyos_scouts_list` · **Read** · Idempotent

Lists the workspace's scouts: the built-in (default) and custom monitors that look for events such as funding, hiring or leadership changes on watched companies or across the web. Shows each scout's id, whether it is active, its cadence, and how many signals it found (new of total). Returns every scout (there are only a few, so there is no paging). Use heliyos_scouts_get for one scout's query and recent signals, heliyos_signals_list for what scouts found. Returns structuredContent \{scouts:[\{id, name, type, is_active, ...\}]\}.

### Inputs

<ParamField path="type" type="string">
  Only built-in (default) or only custom scouts. One of `default`, `custom`.
</ParamField>

<ParamField path="is_active" type="boolean">
  Only active (true) or only paused and unconfirmed (false) scouts.
</ParamField>

<ParamField path="apply_to" type="string">
  Only scouts with this scope. One of `watchlist`, `selected_watchlist`, `entire_web`.
</ParamField>

<ParamField path="response_format" type="string" default="concise">
  "concise" (default) returns one row per scout; "detailed" returns category, scope, effort and preview state too. One of `concise`, `detailed`.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `scouts`.

### API endpoints

- [List workspace Scouts](/api-reference/scouts/list-workspace-scouts) · `GET /v1/platform/global-scouts`

## Get a scout

`heliyos_scouts_get` · **Read** · Idempotent

Fetches one scout by id: what it looks for (its query), cadence, effort, scope, whether it is active, its preview state (custom scouts) and its signal counts. "detailed" adds the 5 most recent signals with their ids and the full query. Returns structuredContent \{scout, recent_signals?\}.

### Inputs

<ParamField path="scout_id" type="string" required>
  Global scout id from heliyos_scouts_list. A 24-character hex id.
</ParamField>

<ParamField path="response_format" type="string" default="concise">
  "concise" (default) returns the scout with its query cut at 1500 characters; "detailed" returns the full query and the 5 most recent signals. One of `concise`, `detailed`.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `scout`, `recent_signals`.

### API endpoints

- [Get a workspace Scout](/api-reference/scouts/get-a-workspace-scout) · `GET /v1/platform/global-scouts/{id}`
- [List workspace Scout signals](/api-reference/signals/list-workspace-scout-signals) · `GET /v1/platform/global-scouts/{id}/signals`

## Create a scout

`heliyos_scouts_create` · **Write**

Creates a custom scout and starts a preview run of its query. The scout stays inactive until you confirm it: when heliyos_scouts_get shows preview completed, call heliyos_scouts_update with state "confirmed" to activate it on its companies. apply_to: watchlist (every watched company, the default), selected_watchlist (only selected_company_ids, which must be watched companies) or entire_web. The scope cannot be changed later. Scout runs use credits. Calling this twice creates two scouts. Returns structuredContent \{scout\}.

### Inputs

<ParamField path="name" type="string" required>
  Scout name. Up to 200 characters.
</ParamField>

<ParamField path="category" type="string" required>
  A short category label, for example "Funding" or "Hiring". Up to 200 characters.
</ParamField>

<ParamField path="query" type="string" required>
  What to look for, in plain language. For watchlist scopes write it about "the company"; each company's name and website are added when it runs. For entire_web, describe the event anywhere on the web. Up to 5000 characters.
</ParamField>

<ParamField path="cadence" type="string">
  How often it runs: daily, weekly (default) or monthly. One of `daily`, `weekly`, `monthly`.
</ParamField>

<ParamField path="effort" type="string">
  Search depth: low, medium (default) or high. Higher effort costs more credits per run. One of `low`, `medium`, `high`.
</ParamField>

<ParamField path="apply_to" type="string">
  watchlist (default), selected_watchlist or entire_web. Fixed once created. One of `watchlist`, `selected_watchlist`, `entire_web`.
</ParamField>

<ParamField path="selected_company_ids" type="string[]">
  Watched company record ids the scout runs on (only with apply_to selected_watchlist). Up to 1000 items.
</ParamField>

<ParamField path="preview_company" type="object">
  selected_watchlist only: the company the preview runs on.
  <Expandable title="properties">
    <ParamField path="name" type="string" required>
      Company name. Up to 500 characters.
    </ParamField>
    <ParamField path="website" type="string">
      Company website. Up to 2000 characters.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField path="preview_lookback" type="string">
  How far back the preview searches: 1_month (default), 3_months or 6_months. One of `1_month`, `3_months`, `6_months`.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `scout`.

### API endpoints

- [Create a custom Scout](/api-reference/scouts/create-a-custom-scout) · `POST /v1/platform/global-scouts`

## Update a scout

`heliyos_scouts_update` · **Write** · Idempotent

Changes a scout's name, category, query, cadence, effort or selected companies, and/or its state; what you leave out is kept. Changes apply to every company the scout runs on. state: "paused" stops it on every company, "active" resumes it, "confirmed" activates a new custom scout after its preview completed. The scope (apply_to) cannot be changed. To delete a custom scout use heliyos_scouts_delete. Returns structuredContent \{scout\}.

### Inputs

<ParamField path="scout_id" type="string" required>
  Global scout id from heliyos_scouts_list. A 24-character hex id.
</ParamField>

<ParamField path="name" type="string">
  Scout name. Up to 200 characters.
</ParamField>

<ParamField path="category" type="string">
  A short category label, for example "Funding" or "Hiring". Up to 200 characters.
</ParamField>

<ParamField path="query" type="string">
  What to look for, in plain language. For watchlist scopes write it about "the company"; each company's name and website are added when it runs. For entire_web, describe the event anywhere on the web. Up to 5000 characters.
</ParamField>

<ParamField path="cadence" type="string">
  How often it runs: daily, weekly (default) or monthly. One of `daily`, `weekly`, `monthly`.
</ParamField>

<ParamField path="effort" type="string">
  Search depth: low, medium (default) or high. Higher effort costs more credits per run. One of `low`, `medium`, `high`.
</ParamField>

<ParamField path="selected_company_ids" type="string[]">
  Replaces the selected companies (selected_watchlist scouts only). Up to 1000 items.
</ParamField>

<ParamField path="state" type="string">
  "active", "paused", or "confirmed" (activate a custom scout once its preview completed). Applied after the field changes. One of `active`, `paused`, `confirmed`.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `scout`.

### API endpoints

- [Update a custom Scout](/api-reference/scouts/update-a-custom-scout) · `PATCH /v1/platform/global-scouts/{id}`
- [Set a workspace Scout state](/api-reference/scouts/set-a-workspace-scout-state) · `POST /v1/platform/global-scouts/{id}/state`

## Delete a scout

`heliyos_scouts_delete` · **Destructive** · Idempotent

Permanently deletes one custom scout and stops it on every company it runs on. Built-in (default) scouts cannot be deleted; pause them with heliyos_scouts_update state "paused". Signals it already found are kept. This cannot be undone: confirm with the user first. Returns structuredContent \{scout_id, deleted, deleted_company_scouts\}.

### Inputs

<ParamField path="scout_id" type="string" required>
  Global scout id from heliyos_scouts_list. A 24-character hex id.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `scout_id`, `deleted`, `deleted_company_scouts`.

### API endpoints

- [Delete a custom Scout](/api-reference/scouts/delete-a-custom-scout) · `DELETE /v1/platform/global-scouts/{id}`

## Add scouts to a company

`heliyos_companies_scouts_add` · **Write**

</ParamField>

## List signals

`heliyos_signals_list` · **Read** · Idempotent

Lists signals (events scouts found, such as a funding round or a leadership change), newest first. Filter by company_id, by scout_id (a global scout from heliyos_scouts_list) and by status (new = unread). Each signal shows its id, date, company and a summary; detailed adds source URLs. Mark them read with heliyos_signals_mark_read. Returns structuredContent \{signals:[\{id, status, detected_at, company_id, company_name, summary\}], next_cursor\}.

### Inputs

<ParamField path="company_id" type="string">
  Only signals about this company record. A 24-character hex id.
</ParamField>

<ParamField path="scout_id" type="string">
  Only signals found by this global scout. A 24-character hex id.
</ParamField>

<ParamField path="status" type="string">
  new (unread), read or archived. One of `new`, `read`, `archived`.
</ParamField>

<ParamField path="limit" type="integer" default="20">
  Signals per page, 1 to 100. Default 20. From 1 to 100.
</ParamField>

<ParamField path="cursor" type="string">
  next_cursor from the previous page, with the same limit. Omit for the first page. Up to 200 characters.
</ParamField>

<ParamField path="response_format" type="string" default="concise">
  "concise" (default) returns one line per signal; "detailed" returns full summaries, source URLs and relevance. One of `concise`, `detailed`.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `signals`, `next_cursor`.

### API endpoints

- [List workspace Scout signals](/api-reference/signals/list-workspace-scout-signals) · `GET /v1/platform/global-scouts/{id}/signals`
- [List signals](/api-reference/signals/list-signals) · `GET /v1/platform/signals`

## Mark signals read

`heliyos_signals_mark_read` · **Write** · Idempotent

Marks signals read: either the given signal_ids (1 to 20) or every new signal about one company (company_id). Pass exactly one of the two. Marking a read signal again changes nothing. Returns structuredContent \{marked, failed\} for signal_ids, or \{company_id, marked_count\} for a company.

### Inputs

<ParamField path="signal_ids" type="string[]">
  Signal ids from heliyos_signals_list, 1 to 20. Up to 20 items.
</ParamField>

<ParamField path="company_id" type="string">
  Mark every new signal about this company read. A 24-character hex id.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `marked`, `failed`, `company_id`, `marked_count`.

### API endpoints

- [Mark signals read in bulk](/api-reference/signals/mark-signals-read-in-bulk) · `POST /v1/platform/signals/bulk-read`
- [Mark a signal read](/api-reference/signals/mark-a-signal-read) · `POST /v1/platform/signals/{id}/read`
