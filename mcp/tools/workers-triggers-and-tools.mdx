## List workers

`heliyos_workers_list` · **Read** · Idempotent

Lists the workspace's workers (AI agents): the built-in default ones and custom ones, each with its id, type, active flag, description and triggers. Returns every worker in one page (a workspace has a handful). Use heliyos_workers_get for a worker's instructions, heliyos_runs_list with worker_id for its runs. Returns structuredContent \{workers:[\{id, name, type, is_active, ...\}]\}.

### Inputs

<ParamField path="type" type="string">
  Only built-in (default) or only custom workers. One of `default`, `custom`.
</ParamField>

<ParamField path="is_active" type="boolean">
  Only active (true) or only inactive (false) workers.
</ParamField>

<ParamField path="response_format" type="string" default="concise">
  "concise" (default) returns one row per worker; "detailed" returns each worker's triggers too. One of `concise`, `detailed`.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `workers`.

## Create a worker

`heliyos_workers_create` · **Write**

Creates a custom worker (AI agent) with a name, instructions and, optionally, triggers that start it: on every new task, when mentioned in chat, on named events, or on a cron schedule. It starts active unless is_active is false, and its runs use credits and can change records or send email (consequential actions wait for approval in Heliyos), so confirm with the user first. Names are unique; a repeat fails with CONFLICT. Before calling: heliyos_triggers_list for valid event names and heliyos_workers_tools_list for the tool_names it may use (both are checked; unknown names are refused). Files are configured in the Heliyos web app. Returns structuredContent \{worker\}.

### Inputs

<ParamField path="name" type="string" required>
  Worker name, unique in the workspace. Up to 200 characters.
</ParamField>

<ParamField path="instructions" type="string" required>
  What the worker does and how, in Markdown. Up to 50000 characters.
</ParamField>

<ParamField path="description" type="string">
  One line shown in the worker catalog. Up to 2000 characters.
</ParamField>

<ParamField path="is_active" type="boolean">
  Default true.
</ParamField>

<ParamField path="read_only" type="boolean">
  true: the worker may read but never change data. Default false.
</ParamField>

<ParamField path="memory_enabled" type="boolean">
  true: the worker keeps memory across runs. Default from the workspace.
</ParamField>

<ParamField path="triggers" type="object[]">
  When the worker runs. Replaces the current triggers; on a default worker its built-in triggers stay. Event names must come from heliyos_triggers_list. Up to 50 items.
  <Expandable title="item properties">
    <ParamField path="type" type="string" required>
      task_created (every new task), mention (@worker in chat), event (named events) or scheduled (cron). One of `task_created`, `mention`, `event`, `scheduled`.
    </ParamField>
    <ParamField path="events" type="string[]">
      event only: event names such as "task.created" or "deal.updated". Up to 200 items.
    </ParamField>
    <ParamField path="cron" type="string">
      scheduled only: 5-field cron, for example "0 8 * * 1-5".
    </ParamField>
    <ParamField path="timezone" type="string">
      scheduled only: IANA zone, for example "Europe/Berlin". Default UTC. Up to 64 characters.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField path="tool_names" type="string[]">
  The tools the worker may call, by name from heliyos_workers_tools_list (Heliyos tools and integration actions alike). Unknown names are refused. Custom workers only. Up to 500 items.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `worker`.

- [Create a worker](/api-reference/workers-and-runs/create-a-worker) · `POST /v1/platform/agents`

## Update a worker

`heliyos_workers_update` · **Write** · Idempotent

Changes a worker by id; what you leave out is kept. Custom workers: name, instructions, description, is_active, read_only, memory_enabled, triggers and tool_names. Default (built-in) workers: only instructions, description, is_active, memory_enabled and triggers; the rest is ignored. `triggers` REPLACES the worker's own triggers (a default worker keeps its built-in ones) and `tool_names` REPLACES its tools: pass every tool it should keep (heliyos_workers_get detailed shows the current ones, heliyos_workers_tools_list the valid names). Set is_active false to pause a worker. Returns structuredContent \{worker\}.

## List tools a worker can use

`heliyos_workers_tools_list` · **Read** · Idempotent

Lists the tools a worker may be given (the names to put in `tool_names` on heliyos_workers_create / heliyos_workers_update): Heliyos's own tools (source builtin) and the actions of the workspace's connected integrations (source action, for example sending email through the connected mailbox). Each has a risk class; communicate, write_crm and external tools do things people will want to review. Call it before creating a worker. Returns every tool in one page. Returns structuredContent \{tools:[\{name, label, description, source, risk, provider\}]\}.

### Inputs

<ParamField path="source" type="string">
  Only Heliyos's own tools (builtin) or only integration actions (action). One of `builtin`, `action`.
</ParamField>

<ParamField path="provider" type="string">
  Only one integration's actions, for example gmail or hubspot. Up to 100 characters.
</ParamField>

<ParamField path="search" type="string">
  Plain words matched against names, labels and descriptions. Up to 200 characters.
</ParamField>

<ParamField path="response_format" type="string" default="concise">
  "concise" (default) returns name, label, description, source and risk; "detailed" returns each tool's input schema too. One of `concise`, `detailed`.
</ParamField>

### Returns

A readable text summary, plus `structuredContent` with `tools`.
