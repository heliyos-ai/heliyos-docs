## Base URL

```text
https://api-prod.heliyos.ai
```

Workspace data lives under `/v1/platform`. Team members, roles and the knowledge base live under `/v1/auth`. Both take the same API key.

## Version

This reference documents **Heliyos API v1.0.0**. The major version is in every path (`/v1/`). New endpoints and new optional fields arrive without a new major version, and the [Changelog](/changelog) lists each change. The MCP server `@heliyos/mcp` v1.0.0 calls this version.

## Authentication

Send your workspace API key as a bearer token on every request. See [Authentication](/authentication).

```bash
-H "Authorization: Bearer $HELIYOS_API_KEY"
```

## Requests

- Bodies are JSON. Send `Content-Type: application/json`.
- Ids are 24-character hexadecimal strings, such as `66f1a8c3e4b0a1b2c3d4e5f6`.
- Dates are ISO 8601 in UTC, such as `2026-11-04T09:30:00.000Z`.
- Unknown body and query keys are dropped before the request is handled.
- `PATCH` changes only the fields you send. Each endpoint says when a field replaces a whole list.

## Responses

Every success answers with the same envelope. `data` holds the resource or list. `meta.message` is a short human-readable summary. Lists add `meta.pagination`.

```json
{
  "meta": {
    "message": "Notes fetched successfully.",
    "pagination": {
      "limit": 20,
      "next_cursor": "NjZmMWE4YzNlNGIwYTFiMmMzZDRlNWY2"
    }
  },
  "data": [
    {
      "_id": "6720b1f4c2a9e3d1f0a4b5c6",
      "title": "Pricing call follow-up"
    }
  ]
}
```

A few deletes answer `204 No Content` with no body. Their pages say so.

Errors use a separate envelope with a stable `error.code`. See [Errors](/api-reference/errors).

| [Activities](/api-reference/activities/list-record-events) | The change history of records and tasks: who changed what, and when. |

| [Labels](/api-reference/labels/list-label-groups) | Label groups that classify email. |

| [Notification settings](/api-reference/notification-settings/get-notification-settings) | Who gets workspace email notifications. |
